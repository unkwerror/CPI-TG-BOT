# Устойчивый запуск Mini App — 7 сентября 2026

Релиз: `startup-resilience-20260907-r1`, только веб-приложение.
База данных, API, бот, worker, балансы и привязки не меняются; миграции не нужны.

## Причина и исправление

Оба внешних SDK загружались с `beforeInteractive`: зависший запрос к Telegram или MAX
останавливал гидратацию даже в другом мессенджере. Статический экран оставался на
«Кот подключается», запрос авторизации ещё не начинался. Зависший ответ API приводил
к тому же экрану: стартовая последовательность не имела ограничения ожидания.

Теперь `MessengerSdk` выбирает SDK по текущим данным запуска и загружает его после
гидратации, без ожидания со стороны входа. Данные входа по-прежнему берутся из URL,
Telegram sessionStorage или доступного SDK; их подпись проверяет неизменённый сервер.
Поздно загрузившийся SDK инициализируется один раз. Ошибки необязательного bridge
не прерывают авторизацию; без SDK остаются обычные браузерные действия.

Вся последовательность авторизации и загрузки `/me` ограничена 15 секундами.
При тайм-ауте запрос отменяется и показывается ошибка с кнопкой «Повторить».
Закрытие компонента тоже отменяет вход. Поздние ответы и прерванное чтение JSON
не сохраняют устаревшую сессию и не заменяют экран ошибки. Другие операции API,
включая покупки и загрузки файлов, не получают новых тайм-аутов или автоповторов.

## Проверка

- `npm test`: отмена входа, запрет сохранения поздней сессии, безопасная инициализация SDK.
- `npm run build -w @cpi/web`: production-сборка и TypeScript.
- `tests/e2e/startup-resilience.spec.ts`: недоступный/зависший SDK каждого мессенджера,
  вход по данным URL без SDK, поздняя инициализация, исключение bridge, тайм-ауты
  `/auth/telegram`, `/auth/session`, `/me` и успешный повтор.
- `tests/e2e/native-studio.spec.ts` и `tests/e2e/messenger-parity.spec.ts`: сохранность
  магазина, Leader-ID, проектов и одной компактной карточки коворкинга.

Браузерные сценарии используют API-моки и не меняют production-данные.
Зависание внешних запросов воспроизведено, но конкретный неответивший запрос на
устройстве участника по серверным логам определить нельзя. Белый экран до загрузки
HTML также требует отдельной проверки соединения/кэша, а не сброса аккаунта.
