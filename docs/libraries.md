# Библиотеки и готовые реализации

Аудит сделан для кошелька баллов, временных QR, конструктора мероприятий и
артефактов, магазина, ленты, админки и загрузки в S3-совместимое хранилище
Beget. Цель — переиспользовать зрелые решения там, где они действительно
сокращают собственный security- и infrastructure-код, не добавляя второй
источник истины.

## Проверены, но сейчас не добавлены

| Решение                                                                                                                   | Решение и причина                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`Uppy` + `@uppy/aws-s3`](https://uppy.io/docs/aws-s3/)                                                                   | Подходит для обычного S3/multipart и остаётся кандидатом на resumable uploads. Текущий протокол дополнительно атомарно создаёт submission/artifact, применяет idempotency, лимиты конкретного поля формы, карантин и последующую reward-оценку. Замена перед первым релизом увеличила бы риск; существующий uploader уже поддерживает multipart, progress, retry и abort для Beget. |
| [`React Hook Form`](https://react-hook-form.com/) + [`@hookform/resolvers`](https://github.com/react-hook-form/resolvers) | Полезны для больших статических форм. Здесь поля приходят из опубликованной версии конструктора, а файлы имеют отдельный асинхронный lifecycle. Текущий узкий renderer короче адаптера RHF и не создаёт второй слой состояния. Вернуться к решению стоит при появлении conditional logic/многостраничных форм.                                                                      |
| [`TanStack Query`](https://tanstack.com/query/latest/docs/framework/react/overview)                                       | Сильный кандидат при росте количества экранов и cache-sharing. В текущем Mini App одна активная wallet-сессия и несколько коротких запросов; внедрение сейчас потребовало бы переписать уже проверенные loading/error/polling flows без изменения бизнес-гарантий.                                                                                                                  |
| [`XState`](https://stately.ai/docs/xstate)                                                                                | Не используется как второй автомат состояний: QR, intent, заказ и reset уже имеют persisted state machine, разрешённые переходы и блокировки в PostgreSQL. Клиент отображает состояние сервера.                                                                                                                                                                                     |
| [`Blnk`](https://github.com/blnkfinance/blnk)                                                                             | Зрелое ledger-ядро, но это отдельный сервис и отдельный операционный контур. Для 100–200 участников он дублировал бы PostgreSQL и усложнил атомарность с заказами/наградами.                                                                                                                                                                                                        |
| [`Medici`](https://github.com/flash-oss/medici)                                                                           | Не подходит: библиотека рассчитана на MongoDB/Mongoose, проект уже транзакционно работает на PostgreSQL.                                                                                                                                                                                                                                                                            |
| [`Form.io`](https://help.form.io/developers/form-builder) / [`JSON Forms`](https://jsonforms.io/docs/)                    | Слишком широкий schema/runtime для шести доменных типов полей. Наши версии формы, file policies и reward rules должны оставаться частью общей PostgreSQL-транзакции.                                                                                                                                                                                                                |

Motion MCP, видео-генерация и внешние Motion API-ключи в проекте не используются. Motion
подключён только как локальная UI-зависимость React; кошелёк не зависит от внешнего
motion-сервиса во время выполнения.
